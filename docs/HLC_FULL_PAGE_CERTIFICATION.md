## Certification rule
A route is not DONE until all applicable columns pass: Mobile, Desktop, Function, Navigation, Imagery/Branding, Links/Transitions.

Status legend: `PASS` = verified, `FIX` = known issue under correction, `CHECK` = needs review, `N/A` = not applicable, `CLOSED` = already independently certified and production-verified.

## Screenshot protocol
For each route, capture only what is needed to judge it:
1. top/hero or first viewport;
2. middle/content/form state when meaningful;
3. bottom/CTA/footer or success/empty/error state when meaningful.

For mobile, use a real iPhone where visual behavior cannot be trusted to automation alone. Desktop may use exact-head rendered evidence unless a defect requires physical confirmation.

## Imagery rule
Images are purposeful, not decorative filler. Prefer imagery that explains the resident/professional journey, shows service context, builds trust, or improves an otherwise dense section. Avoid repeated stock photography, image walls, duplicate logos, and imagery that implies a provider/job outcome HLC has not confirmed.

## Final end-to-end certification
After all route rows pass, perform these complete journeys without direct URL jumping:
- Public Home → request service → submit → confirmation → contact/help.
- Public Home → professionals → professional application.
- Login → correct authenticated landing → core workspace navigation.
- Lead/request → communication → schedule/calendar → job/completion path where seeded test data permits.
- Legal/accessibility/support links from normal navigation and footer entry points.
